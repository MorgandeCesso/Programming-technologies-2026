## 2. Ход работы
**Провайдер.** Вместо платного OpenAI использован бесплатный Groq (по таблице бесплатных API из методички): `base_url=https://api.groq.com/openai/v1`, модель `openai/gpt-oss-20b` (reasoning-модель). Groq совместим с библиотекой `openai`, поэтому используется `client.chat.completions.create`.

**Окружение.** Создано виртуальное окружение, установлены `openai` и `python-dotenv`, ключ хранится в `.env` (добавлен в `.gitignore`), зависимости зафиксированы в `requirements.txt`.

**Базовый бот.** `client.chat.completions.create(model=..., messages=...)`, ответ берётся из `response.choices[0].message.content`. Главный цикл читает ввод, выход по `exit`, ошибки API (`AuthenticationError`, `RateLimitError`, `APIConnectionError`, `APITimeoutError`, `BadRequestError`) обрабатываются без падения программы.

### Задание 1. Системные промпты
- Промпт передаётся первым сообщением с ролью `system` (аналог `instructions`/`developer` в Responses API).
- Источники: переменная `SYSTEM_PROMPT` в `.env`, выбор из базы SQLite (`prompts.db`, таблица `prompts`: id, name, text) или ручной ввод с сохранением в БД.
- Хотсвап: команда `/prompt` меняет промпт прямо во время диалога, история при этом сохраняется. Дополнительно `/prompts`, `/add`, `/del`.

**Как системный промпт передаётся в API.** В `main.py`, функция `build_params`, промпт добавляется первым сообщением с ролью `system`:
```python
if instructions:
    msgs = [{"role": "system", "content": instructions}] + msgs
params = {"model": model, "messages": msgs}
```
Для сравнения, в Responses API (OpenAI) тот же промпт передаётся одним из двух способов:
```python
# способ 1: параметр instructions
client.responses.create(model="gpt-6-luna", instructions=prompt, input=history)

# способ 2: сообщение с ролью developer в input
client.responses.create(
    model="gpt-6-luna",
    input=[{"role": "developer", "content": prompt}] + history,
)
```
Роль `system` в Chat Completions и `developer`/`instructions` в Responses API выполняют одну функцию: задают поведение модели поверх реплик пользователя. На Groq (Chat Completions) используется роль `system`.

### Отличия от условия задания
Работа выполнена на бесплатном провайдере Groq (из таблицы методички), поэтому часть пунктов реализована эквивалентно:
- Вместо Responses API используется Chat Completions: системный промпт передаётся сообщением с ролью `system` (аналог `instructions`/`developer`), история сообщений передаётся в `messages` (аналог `input`).
- У модели `openai/gpt-oss-20b` значение `reasoning_effort=none` не поддерживается, поэтому сравнивались `low`, `medium` и `high`.
- Ограничение «`temperature` только при `effort=none`» относится к моделям OpenAI. На Groq температура принимается при любом `effort`, поэтому она менялась независимо.
- Первоначально работа разрабатывалась под OpenAI API (`gpt-6-luna`), но на аккаунте не было кредитов (ошибка 429 `credit_balance_exhausted`), поэтому был выполнен переход на Groq.
- Conversation API не использовался: история ведётся вручную (допускается заданием).

### Задание 3. История диалога
В `messages` передаётся список сообщений `{"role": ..., "content": ...}`; после каждого сообщения история обрезается до последних 6 (3 пользователя + 3 ассистента) срезом `history[-6:]`. Если запрос завершился ошибкой, вопрос удаляется из истории. Проверка: бот сообщает имя, затем в следующей реплике отвечает на вопрос «Как меня зовут?»; после более чем 3 обменов самые ранние реплики «забываются». Команды `/history` и `/clear`.
