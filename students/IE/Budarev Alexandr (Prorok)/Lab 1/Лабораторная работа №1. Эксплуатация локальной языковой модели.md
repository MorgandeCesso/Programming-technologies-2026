## Цель и задачи

Цель - выбрать языковую модель для локального ИИ-помощника: запустить модели на своём компьютере и сравнить их через локальный сервер LM Studio учебных задачах.

Локальная модель: бесплатна, работает без интернета, а вопросы и код не уходят на чужие серверы - запросы идут на `localhost`.
Ограничение одно - модель должна быстро работать на ноутбуке без видеокарты.

Задачи:
1. Выбрать две модели на Hugging Face для запуска в LM Studio.
2. По очереди проверить работу обеих моделей на локальном сервере.
3. Подготовить пять запросов: объяснение понятия, функция на Python, поиск ошибки в коде, извлечение данных в JSON, вопрос без ответа в тексте с фразой «Если информации недостаточно, сообщи об этом».
4. Отправить одинаковые запросы обеим моделям, зафиксировать название, число параметров, квантование и настройки запуска.
5. Для одной модели выполнить один запрос по три раза при temperature 0.2 и 1.0.
6. Сравнить время полного ответа, корректность и соблюдение формата.
7. Сделать вывод, какая модель лучше подходит компьютеру и задачам, описать ограничения.

## 1. Выбор моделей

Взяты две модели из разных семейств и разного размера, чтобы сравнить качество и скорость при разных бюджетах памяти. Обе скачаны через поиск LM Studio в формате `.gguf` и квантовании Q4_K_M.

|                       | Qwen3.5-4B          | Dale 0.8B    |
| --------------------- | ------------------- | ------------ |
| Идентификатор в API   | `qwen3.5-4b`        | `dale-0.8b`  |
| Разработчик           | lmstudio-community | manuelgscom  |
| Архитектура           | Qwen3.5             | Qwen3.5-0.8B |

| Квантование           | Q4_K_M              | Q4_K_M       |
| Максимальный контекст | 262 144             | 262 144      |

Оценка памяти под веса по формуле из методички:

для 4B при 4 битах: M ≈ N · b / 8 = 4·10⁹ · 4 / 8 = 2·10⁹ байт **≈ 2 ГБ**

Для 0.8B при 4 битах: M ≈ 0.8·10⁹ · 4 / 8 = 0.4·10⁹ байт **≈ 0.4 ГБ**

Реальный файл больше: в Q4_K_M часть весов хранится с большей точностью, плюс в файле есть служебные данные.

Модели лежат в Models Directory LM Studio по структуре из методички: организация, модель, файл `.gguf`.

## 3. Набор запросов и эксперимент

### 3.1. Набор запросов

Запросы подобраны как типичные задачи: разобраться в теме, написать функцию, найти ошибку в своём коде, достать данные из текста и ответить на вопрос по конспекту, не выдумывая. Они собраны в `experiment.py`:

| №   | Задача              | Запрос                                                                                      | Что проверяется                                                       |
| --- | ------------------- | ------------------------------------------------------------------------------------------- | --------------------------------------------------------------------- |
| 1   | Объяснение понятия  | что такое рекурсия, с примером на Python                                                    | понятность и точность                                                 |
| 2   | Функция на Python   | напиши небольшую функцию на Python                                                          | чистота и работоспособность кода                                      |
| 3   | Поиск ошибки        | `average()` с циклом `range(1, len(numbers))`                                               | цикл пропускает первый элемент: для [2, 4, 6] выходит 3.33 вместо 4.0 |
| 4   | Извлечение в JSON   | вернуть ТОЛЬКО JSON с 7 ключами                                                             | валидный JSON, все ключи, `age` и `start_year` – числа                |
| 5   | Ответа нет в тексте | сколько стоит подписка (цены в тексте нет) + «Если информации недостаточно, сообщи об этом» | не выдумает ли модель цену                                            |

У запросов 2–5 один правильный ответ, поэтому их можно проверить объективно.
### 3.2. Отправка запросов к обеим моделям

`experiment.py` отправляет все пять запросов каждой модели с одинаковыми настройками:

```python
start = time.perf_counter()
response = client.responses.create(
    model=model,
    input=prompt,
    temperature=TEMPERATURE,
    max_output_tokens=MAX_TOKENS,
)
seconds = time.perf_counter() - start
```

`time.perf_counter()` засекает время до и после запроса – это время получения полного ответа. `response.usage.output_tokens` - длина ответа в токенах, скорость считается как токены / секунды. Для запроса 4 программа проверяет формат: ответ должен целиком разбираться `json.loads`. Остальные ответы проверены вручную, код из ответов запущен. Все ответы сохраняются в `results_experiment.md`.

2. **Написание функции на Python.** Модель справилась с задачей еще на первой, написав несколько функций с рекурсией. 
3. **Поиск ошибки.** Модель справилась с задачей поиска ошибки в функции на языке Python.
4. **JSON.** Модель справилась с задачей генерации JSON файла из предоставленных данных.
5. **Нет ответа.** Модель объявила о недостаточной информации в тексте, для ответа на поставленный вопрос.
Примерное время ответа 3-7 секунд.

## Вывод

В ходе работы на компьютере с процессором AMD Ryzen 5 2600, 8 ГБ оперативной памяти и без дискретной видеокарты обе модели были успешно запущены локально и протестированы через сервер LM Studio на порту 7000.

**Лучшей для локального ИИ-помощника студента признана Qwen3.5-4B.** Она стабильно и корректно справилась со всеми пятью задачами: объяснила рекурсию с примерами, написала рабочий код, нашла ошибку в `average()`, вернула валидный JSON со всеми ключами и честно сообщила о недостатке информации, не выдумав цену. По суммарному времени она ответила немного быстрее (18 с против 20 с у Dale), а по скорости генерации превзошла соперницу почти вдвое - 141,7 ток/с против 79,0 ток/с.

**Dale 0.8B** при меньшем размере (0,8 млрд параметров) показала себя хуже в универсальных задачах: при объяснении рекурсии и поиске ошибки модель **зацикливалась** и генерировала ответ до принудительной остановки, JSON выдала «сырым», без форматирования. При этом она быстрее загружается и занимает меньше памяти (≈0,4 ГБ против ≈2 ГБ у Qwen), а на простых задачах (написание функции, вопрос без ответа в тексте) справилась корректно.

**Влияние температуры** проверено на обеих моделях. У Qwen3.5-4B при temperature 0.2 все три ответа совпали и ошибок не было, а при 1.0 один ответ из трёх отличался, и появились ошибки (3 из 3 попыток формально дали JSON, но с нарушениями). У Dale 0.8B ответы остались одинаковыми при обеих температурах, ошибок не зафиксировано - вероятно, из-за очень малого числа параметров модель почти не варьирует выбор токенов. Это подтверждает общий принцип: для строгого формата (JSON) нужна низкая температура.

**Обнаруженные ограничения:**

- **8 ГБ ОЗУ - жёсткий лимит.** Модель на 4 млрд параметров в Q4_K_M занимает около 2 ГБ только под веса, плюс KV-кэш под контекст 8192 - на 8 ГБ остаётся мало запаса, приходится закрывать другие программы.
- **Dale 0.8B склонна к зацикливанию** на задачах рассуждения (рекурсия, поиск ошибки) - это делает её непригодной для универсального помощника без ручного контроля длины ответа (`max_output_tokens`).
- **Скорость на CPU без GPU** невысокая: развёрнутые ответы занимают 3-7 секунд, а при зацикливании Dale ответ приходится обрывать вручную.
- **Режим рассуждений (thinking)** нужно держать выключенным - на слабом CPU он съедает лимит токенов.
- **Контекст 8192** выбран как компромисс: запросы короткие, а максимальный контекст 262 144 токена на 8 ГБ ОЗУ использовать нельзя - KV-кэш занял бы всю память.

**Итог:** для студенческого ноутбука без видеокарты и с 8 ГБ ОЗУ оптимальна **Qwen3.5-4B в квантовании Q4_K_M** с контекстом 8192 и temperature 0.2. Dale 0.8B можно рекомендовать только как лёгкую модель для простых коротких задач, где не требуется рассуждение, - при условии ограничения длины ответа, чтобы избежать зацикливания.
